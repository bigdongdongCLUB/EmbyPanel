# 点播积分规则

每位用户每月获得管理员设置的初始积分，默认 300 积分，每月 1 日上海时间 00:00 重置。不累积、不结转，当月用完需等待下月重置。提交点播仍需有效订阅。

每人每日最多成功提交 3 次申请（默认值，可由管理员调整），消耗积分和免积分申请均计入次数。取消确认、提交失败或重复申请被拒绝不计次；删除时为“待处理”的申请会恢复当天次数，删除其他状态申请不恢复次数。判定以删除时状态为准，后续管理员状态变化不影响已恢复的次数。每日上海时间 00:00 重置，用户可在“我的点播”查看“本日可用申请”。

| 点播内容 | 消耗积分 |
| --- | --- |
| 电影（所有发行年份） | 每部 10 |
| 2015 年及以后发行的电视剧季（含 2015） | 每季 10 |
| 2005—2014 年发行的电视剧（含 2005） | 每季 20 |
| 2005 年以前发行的电视剧 | 每季 30 |

电视剧以所点播季的发行年份为准，由服务器核实 TMDB 数据。年份缺失按 30 积分处理，最高 30 积分；查询失败则暂不提交，请稍后重试。

## 预占、扣除与归还

已入库的电影或所选电视剧季再次提交不消耗积分（0 积分）。点播其他尚未入库的季仍按该季发行年份扣除积分。点击“提交申请”后会提示“该内容已入库，你确定再次提交吗？”，取消则不提交。

- 提交请求时预占积分；可用积分 = 配置的每月初始积分 - 当月已扣积分 - 当月预占积分。
- 管理员标记“已入库 / 已完成”时才实际扣除。重复操作不会重复扣除。
- “无资源”“无法更新”释放预占。撤销“已入库 / 已完成”时归还已扣积分。
- 重新进入待处理或进行中时，可以再次预占积分。
- 积分不足时整次管理员状态变更失败，提示积分不足。
- 删除未入库点播释放预占；删除已入库记录不退还已扣积分，账本独立保留。管理员之后仍可处理用户已删除的点播，入库时照常结算。

## 跨月与历史数据

- 未用完积分不结转。月初切换管理员配置的初始积分额度，不依赖 worker 定时发放。
- 积分仅在提交当月结算。旧月待处理的预占不占用新月额度。
- 跨月后无论标记已入库、无资源或其他状态，均不再扣除或返还积分。

## 部署与检查

执行数据库迁移 `npx prisma migrate deploy`，并生成客户端 `npx prisma generate` 后构建运行。安装与升级脚本已有迁移步骤。

规则与时间边界测试：`node --test tests/vod-points.test.mjs`。
本机数据库事务测试：`RUN_VOD_POINTS_DB_TESTS=1 node --test tests/vod-points.test.mjs`；测试数据在事务结束时全部回滚。

用户可在“我的点播”标题旁的规则 icon 查看规则。

管理员可在系统设置 → 点播功能中调整“每月初始积分数”（0—100000，默认 300）。保存后按新额度计算当前可用积分，保留已扣和预占记录；设为 0 后仍可提交已入库的免积分内容。

“每日每人提交次数”位于月度积分设置下方，支持 1—1000 次，默认 3 次。保存后立即按新上限计算当天剩余次数。
